# ИИ-модуль Rat AI

Наша часть — локальное обнаружение событий по видео, обучение, оценка качества,
таймкоды, кадры-доказательства и привязка к проверенным правилам. Сервер загрузки,
очередь заданий и пользовательский интерфейс разрабатываются другими участниками.

Для коллег: [установка, Python API и контракт интеграции](INTEGRATION.md).
Экспериментальные веса без исходной разметки включены в `rat_ai/artifacts/`;
датасет для первого запуска не нужен.

## Подготовка обучающей выборки

Нужен Python 3.11+ и зависимости из `requirements-data.txt`.
Из корня репозитория:

```powershell
python -m pip install -r ai/requirements-data.txt
python ai/tools/prepare_dataset.py --data-root "C:\path\to\open" --output ai/local/dataset
python -m unittest discover -s ai/tests -v
```

В указанной папке должны находиться `open_labels.xlsx` и `videos/`. Допускается
дополнительный вложенный каталог `open/`, как в исходном архиве.

Подготовка проверяет соответствие файлов и строк таблицы, метки и границы
таймкодов. Латинская X и кириллическая Х нормализуются только в идентификаторах;
исходные имена файлов сохраняются. Длительность и размеры берутся из контейнера
MOV. Это не проверка декодирования или визуального содержания.

Результаты сохраняются локально в игнорируемой Git папке `ai/local/dataset/`:

- `manifest.jsonl`: путь, метка, таймкод, метаданные, SHA-256 и выборка каждого видео.
- `summary.json`: размеры выборки, длительности и точные дубликаты.
- `event_review.csv`: поля для ручного уточнения действия, типа события, правила
  и группы съёмки. Повторный запуск не перезаписывает эту таблицу.

Разделение предварительное: около 20% групп уникальных видео каждого класса
выделяются для валидации с seed 42. Байтовые копии всегда остаются в одной группе.
Разные таймкоды одного файла сохраняются отдельными исходными аннотациями.
Точки событий не задают начало и конец действия и не превращают остальное
видео в подтверждённые отрицательные примеры.

Перед следующим обучением нужно просмотреть ролики локально, уточнить категории
и группы связанных дублей/сессий. Для импорта ручной разметки есть `--review`,
для разделения по полю `session_group` — `--group-by-session`.
Без этих параметров сохраняется исходное предварительное разделение по точным
копиям. Близкие по содержанию дубли не выявляются одним SHA-256.
Пошаговая инструкция и локальная страница просмотра: [REVIEW.md](REVIEW.md).
Валидацию нельзя использовать для обучения, подбора описаний по отдельным
ответам или ручного запоминания событий. При обучении следует исключить
повторный учёт точных копий, сохранив все подтверждённые отметки событий.

## Дообучение компактного детектора на CPU

Отдельный детектор `mobilenet_v3_small_temporal_v1` использует предобученный
MobileNetV3 Small и три кадра двухсекундного фрагмента. Веса ранних визуальных
блоков заморожены. Дообучаются последний свёрточный блок и новый классификатор,
который получает среднее представление, разность крайних кадров и среднее
абсолютное изменение соседних кадров. Веса Qwen этим обучением не изменяются.

```powershell
ai/.venv/Scripts/python.exe -m pip install -r ai/requirements-training.txt --index-url https://download.pytorch.org/whl/cpu
ai/.venv/Scripts/python.exe ai/tools/train_detector.py --epochs 15 --threads 4
```

Второй проход с плотными отрицательными окнами только из обучающей выборки:

```powershell
ai/.venv/Scripts/python.exe ai/tools/train_detector.py --epochs 15 --threads 4 --dense-negative-stride-sec 2 --warm-start ai/local/training/mobilenet-temporal-v1/best_detector.pt --output ai/local/training/mobilenet-temporal-v2
```

Первый запуск скачивает около 10 МБ предобученных весов MobileNet из официального
каталога PyTorch и проверяет хеш. Затем всё обучение и проверка видео выполняются
локально. Источник: https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html
Лицензия torchvision: https://github.com/pytorch/vision/blob/main/LICENSE

Точные копии видео группируются по SHA-256. Обучение использует 32 уникальных
ролика, валидация — 8; копии не пересекают выборки. Все отметки событий точных
копий сохраняются. Положительные обучающие окна центрируются на отмеченных
событиях с небольшим сдвигом, отрицательные берутся только из роликов с меткой
«без нарушения». Неотмеченные части положительного видео не становятся
отрицательными примерами. На вход модели не передаются имя файла или метаданные.

Для экономии памяти замороженные представления кэшируются. Последний визуальный
блок действительно получает градиенты; изменение его параметров измеряется
и сохраняется в отчёте. BatchNorm использует исходную статистику, изображения
вписываются в квадрат 224×224 без обрезания краёв сцены.

Файлы в `ai/local/training/mobilenet-temporal-v1/`:

- `status.json`: текущий этап и эпоха.
- `best_detector.pt`: полный обученный детектор с замороженными и изменёнными слоями.
- `report.json`: история потерь, число обученных параметров и ошибки на валидации.
- `prefix_features.pt`: локальный кэш производных данных; не публиковать.

Контрольная эпоха выбирается по сбалансированной ошибке размеченных окон
валидации. После обучения каждый валидационный ролик сканируется целиком с шагом
2 секунды, без использования его размеченного таймкода для выбора входных окон.
Вердикт для измерения качества получается из максимального балла при пороге 0.5.
Эти показатели относятся к валидации на восьми видео, а не к независимому тесту.
Группы связанных съёмок ещё требуют ручного уточнения.

Запуск на новом видео без интернета:

```powershell
ai/.venv/Scripts/python.exe ai/tools/infer_detector.py --video "C:\path\video.mov" --checkpoint ai/local/training/mobilenet-temporal-v2/best_detector.pt --output ai/local/prediction.json
```

Выход содержит статистические кандидаты с таймкодами и баллами. Он пока не
назначает типы нарушений и нормативные ссылки и не заменяет полный ответ API
из кейса. Для этого нужны отдельная классификация событий и проверенный
справочник правил. Модель не идентифицирует лица и не обрабатывает звук.

### Результат первых запусков

Оба запуска выполнены локально на CPU. Обучались 167 169 параметров; изменение
последнего визуального блока подтверждено сравнением весов. В v1 использовались
114 обучающих окон, в v2 — 350. Обе версии проходили по 15 эпох, выбранные
контрольные эпохи — 9 и 6 соответственно.

| Проверка целых видео при пороге 0.5 | v1 | v2 |
| --- | --- | --- |
| Найденные положительные видео | 4 из 4 | 4 из 4 |
| Правильно отклонённые нормальные видео | 0 из 4 | 0 из 4 |
| Ложные тревоги | 4 | 4 |
| Accuracy | 0.50 | 0.50 |
| Precision | 0.50 | 0.50 |
| Recall | 1.00 | 1.00 |

Детектор пока не различает нормальные и положительные ролики достаточно надёжно:
все восемь получили срабатывание. Уменьшение ошибки на размеченных окнах не
улучшило итоговое распознавание. Эти веса — экспериментальная исходная точка,
их нельзя считать готовым решением кейса. Типизация событий, более длинный
временной контекст и независимая проверка требуют дальнейшей работы.

## Qwen3-VL-2B для локального анализа и объяснений

Для первого эксперимента выбрана `Qwen/Qwen3-VL-2B-Instruct` (Apache 2.0).
Исполнение — OpenVINO GenAI, с INT4-весами. Загрузчик закрепляет сторонний
экспорт `helenai/Qwen3-VL-2B-Instruct-int4` на ревизии
`61f75fcd9f922da40af9463a30bdd231fe4f6f14`. Это ранний экспорт: его совместимость
и качество нужно подтвердить реальным запуском. Чужой Python-код не загружается
и `trust_remote_code` не включается. Бинарные веса проверяются по SHA-256 LFS,
остальные файлы — по идентификатору Git blob. Контрольные суммы закреплены
в `model-artifacts.lock.json` из исходного API Hugging Face. Происхождение сохраняется рядом
с моделью в `rat_ai_provenance.json`.

Для этого окружения нужен Python 3.12 x64. В подготовленном `ai/.venv`:

```powershell
ai/.venv/Scripts/python.exe -m pip install -r ai/requirements-inference.txt
ai/.venv/Scripts/python.exe ai/tools/check_environment.py
ai/.venv/Scripts/python.exe ai/tools/check_videos.py
ai/.venv/Scripts/python.exe ai/tools/download_model.py --workers 4
ai/.venv/Scripts/python.exe ai/tools/prepare_tokenizer.py
ai/.venv/Scripts/python.exe ai/tools/benchmark_vlm.py --device CPU
ai/.venv/Scripts/python.exe ai/tools/benchmark_vlm.py --device GPU --output ai/local/benchmarks/smoke-gpu
```

Для последовательного первого запуска после установки зависимостей:

```powershell
ai/.venv/Scripts/python.exe ai/tools/first_run.py --mirror --workers 8
```

Сценарий продолжает загрузку, проверяет файлы, подготавливает токенизатор,
проверяет искусственное изображение на CPU и GPU и запускает диагностический
фрагмент одного обучающего ролика. Состояние записывается в
`ai/local/first_run_status.json`; результаты — в `ai/local/benchmarks/`.
Ошибки сохраняются явно. Обучение этот сценарий не выполняет.
`--mirror` переключает источник байтов файлов на `hf-mirror.com`; ожидаемые
контрольные суммы по-прежнему берутся из закреплённого списка исходного Hugging Face API.

Установка зависимостей и загрузчик скачивают только общедоступные зависимости и
веса; подготовка токенизатора и исполнение используют локальные файлы.
Альтернативный транспорт загрузки — `download_model.py --transport hf --workers 2`.
Стандартный загрузчик продолжает частично скачанные файлы при повторном запуске.
Карточка исходной модели: https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct
Пример API исполнения: https://openvinotoolkit.github.io/openvino.genai/docs/use-cases/visual-processing/

По умолчанию benchmark обрабатывает искусственный красный квадрат на белом фоне.
Для видео укажите путь и фрагмент, например:

```powershell
ai/.venv/Scripts/python.exe ai/tools/benchmark_vlm.py --device GPU --video "C:\path\clip.mov" --start-sec 18 --duration-sec 8 --frames 4 --output ai/local/benchmarks/clip-gpu
```

Диагностический запуск получает последовательность изображений с таймкодами и
описательную инструкцию без готовых ответов разметки. Это проверка наблюдений,
а не готовый детектор нарушений. `response.txt` содержит ответ модели и остаётся
локальным. В журнал выводятся только технические метрики, без содержимого видео.
`metrics.json` содержит времена, число кадров и пиковую RSS процесса. RSS
не учитывает все выделения GPU/общей памяти. Замер включает загрузку модели;
для оценки сервиса с постоянно загруженными весами понадобится отдельный замер.
При превышении 300 секунд дочерний процесс останавливается, статус — `failed`.
Перед запуском требуется минимум 3 ГБ доступной RAM. Это защитный порог,
а не подтверждённое требование модели: фактический расход ещё нужно измерить.
При недостатке памяти сохраняется причина `insufficient_available_ram`,
веса не загружаются в память. После освобождения памяти запуск можно повторить.
Для NPU используйте `--device NPU` только после проверки доступности устройства
и совместимости всей мультимодальной модели.

`check_videos.py` проверяет декодирование трёх кадров каждого ролика, включая
начало и конец. Это не полная проверка каждого кадра видео.

## Обучение и оценка

Компактный классификатор уже обучен, но пока не различает события надёжно.
Нужно уточнить типы событий и группы съёмки перед следующим изменением модели.
Название файла, длительность, кодек и метаданные не использовать как признаки нарушения.

Сравнение выполненных прогонов и воспроизводимые команды: [EXPERIMENTS.md](EXPERIMENTS.md).
Сценарий `compare_detectors.py` проверяет совпадение видео, меток, времён сканирования
и порога, пересчитывает ошибки и ROC AUC. Падение числа ложных тревог при росте
пропусков не проходит его проверку улучшения. Публичный результат содержит только
сводные показатели; исходные отчёты с аннотациями остаются в `ai/local/`.

Intel AI Boost рассматривать для исполнения совместимой модели через OpenVINO;
фактическую доступность и скорость CPU/GPU/NPU проверить отдельно.

Минимальные измерения: ошибки на положительных и отрицательных видео, precision,
recall, F1, ошибка локализации во времени и полное время обработки MOV.
Порог и правила объединения соседних срабатываний выбирать на валидации;
для независимой финальной оценки нужны дополнительные отложенные ролики.
Ограничение кейса — 5 минут на полный запрос, включая декодирование и кадры.

## Контракт с бэкендом

Планируемый интерфейс — `analyze_video(video_path)`, возвращающий `verdict`
(`violation` или `no_violation`) и `violations`. Это пока спецификация,
полный адаптер к схеме жюри ещё не добавлен. Рабочий Python API сырых оценок
`VideoDetector.analyze_video()` описан в `INTEGRATION.md`.

Каждое событие содержит `type`, `timecode_sec`, `description`, `evidence_frames`
(1–3 JPEG в base64 с `timestamp_sec`). Дополнительно нужно согласовать `source`
с полями `title`, `section`, `url`: фронтенд уже поддерживает нормативный источник,
а обязательная схема API из кейса не содержит отдельного поля для него.

Нормативные ссылки выбираются из проверенного справочника. Модель не должна
придумывать документы, пункты или невидимые на видео обстоятельства.
Ошибка декодирования/модели передаётся серверу как ошибка задачи, а не как
`no_violation`. Организация заданий, ключей API и HTTP остаётся за бэкендом.

## Локальность данных

Видео, кадры и описания содержимого не отправляются облачным моделям.
Тестовые видео жюри не используются для обучения. Обработка не использует звук
или идентификацию лиц. После загрузки весов исполнение должно работать без сети.
Исходный датасет, кадры, кэши признаков, разметка и полные чекпойнты обучения
не добавляются в Git. Для совместной разработки включён только экспорт числовых
весов без `sample_spec`, кадров и локальных путей.
