# Настоящий детектор через backend и frontend

Общий запуск использует существующие FastAPI, Vite proxy и React-интерфейс из
репозитория. Загруженный ролик обрабатывается обученными весами MobileNet v2,
а backend извлекает JPEG-кадры FFmpeg. Демо-ответы и облачные модели не используются.
Это проверка интеграции; качество v2 по-прежнему недостаточно для сдачи.

## Подготовка

Нужны Python 3.12, Node с поддержкой версии из `frontend/package.json`, FFmpeg и
ffprobe. Установите пакет ИИ по [INTEGRATION.md](INTEGRATION.md), затем из корня:

```powershell
ai/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
cd frontend
npm ci
cd ..
```

## Запуск

Если FFmpeg и ffprobe находятся в PATH:

```powershell
ai/.venv/Scripts/python.exe ai/tools/run_local_stack.py
```

Или передайте локальные исполняемые файлы:

```powershell
ai/.venv/Scripts/python.exe ai/tools/run_local_stack.py --ffmpeg-bin "C:\path\bin\ffmpeg.exe" --ffprobe-bin "C:\path\bin\ffprobe.exe"
```

Откройте http://127.0.0.1:5173, загрузите MOV и нажмите «Проверить видео».
Сервисы слушают только `127.0.0.1`. Общий случайный API-ключ создаётся при запуске
и передаётся только серверным процессам. Он не записывается в `VITE_`-настройки,
статус или Git. Порты можно изменить через `--backend-port` и `--frontend-port`.
Настройки локальных `.env` не нужно менять: команда задаёт окружение запуска.

В интерфейсе появятся **экспериментальные фрагменты для проверки**, баллы и кадры.
Типы нарушений и нормативные ссылки не выдумываются. Пустой результат также
остаётся неопределённым и не превращается в заключение об отсутствии нарушений.
Этот режим не соответствует финальной схеме API жюри; режим backend по умолчанию
остаётся `strict`. Отдельная настройка Docker для этой команды не выполняется.

## Остановка и локальные данные

Для запуска в терминале — Ctrl+C. Из другого терминала:

```powershell
ai/.venv/Scripts/python.exe ai/tools/run_local_stack.py --stop
```

Остановка использует сохранённые PID и время создания процессов, чтобы не
останавливать чужие процессы при повторном использовании PID.
Журналы, статус запуска, SQLite с результатами и служебные файлы находятся
в `ai/local/integration/`, вне Git. Backend удаляет служебную копию ролика после
обработки; результаты с JPEG остаются локально в SQLite до удаления хранилища.
Исходные видео не меняются. Не публикуйте SQLite или журналы с приватными данными.

## Проверка всей цепочки

```powershell
ai/.venv/Scripts/python.exe -m pip install httpx
ai/.venv/Scripts/python.exe ai/tools/smoke_local_stack.py
```

Сценарий создаёт искусственный MOV, отправляет его через настоящий Vite proxy,
ожидает ответ реальной модели и проверяет JPEG и таймкоды. Опция `--video`
позволяет проверить свой локальный MOV. Скрипт принимает только локальный HTTP-адрес
и записывает сводные показатели без кадров и аннотаций в `ai/local/integration/`.
Он проверяет интеграцию и не вычисляет качество распознавания.

Проверка на Windows CPU 17 октября 2026: ручная загрузка искусственного ролика
в UI прошла; восемь валидационных роликов прошли через proxy/API/модель/FFmpeg,
после включения подтверждения двух окон проверены 13 JPEG. Запросы заняли
5.7–9.4 секунды; отдельный запрос на искусственном видео — около 5.9 секунды.
Это измерения на конкретном ноутбуке, а не гарантия для любого видео и нагрузки.
Прошли 50 тестов ИИ и 38 тестов backend. Для неизменённого frontend ранее
прошли 69 тестов и сборка интерфейса; после изменения политики результат
повторно проверен в UI на искусственном ролике.
Сводный отчёт без приватных данных: [evaluation/integration-confirmed.json](evaluation/integration-confirmed.json).

## Сервер Brev A10

Подключение выполняется через `brev shell hizeshi`. На сервере создано отдельное
окружение `~/rat-ai-gpu-env`; установленные версии для обучения перечислены
в `requirements-gpu.txt`. CPU-зависимости ноутбука не нужно устанавливать поверх
CUDA-сборки сервера. Исходники находятся в `~/rat-ai-deploy`.

Собранный Docker-образ frontend `rat-ai-site:night` обслуживает порт 8080.
`deploy_brev.py` запускает API на 127.0.0.1:8000 и nginx с серверным API-ключом.
Ключ, база задач и логи находятся в игнорируемом `ai/local/server/`; ключ не
передаётся в JavaScript. Контейнер имеет политику перезапуска, API запущен отдельным
процессом. После перезапуска сервера нужно повторно вызвать `deploy_brev.py`.

```sh
cd ~/rat-ai-deploy
docker build -t rat-ai-site:night frontend
~/rat-ai-gpu-env/bin/python ai/tools/deploy_brev.py
~/rat-ai-gpu-env/bin/python ai/tools/smoke_local_stack.py --url http://127.0.0.1:8080
```

Сайт использует опубликованный MobileNet для поиска фрагментов и базовую
Qwen2.5-VL-7B для черновых описаний. Четыре дообученных VLM-кандидата не заменили
детектор из-за худших результатов на валидации; см. [EXPERIMENTS.md](EXPERIMENTS.md).

```sh
~/rat-ai-gpu-env/bin/python ai/tools/deploy_brev.py --describe-with-config ~/rat-ai-runs/native-qwen25-7b/config.json --restart-api --replace-frontend
```

Конфигурация сохраняется в приватном `ai/local/server/selection.json`.
Перезапуск API допускается только без ожидающих задач и для принадлежащего
этому проекту процесса. Замена frontend проверяет метку контейнера проекта.
После изменения frontend предварительно пересоберите Docker-образ.

Серверный сквозной тест с описанием на искусственном видео прошёл за 20.7 секунды:
реальный детектор, один кандидат, три JPEG. Качество описаний этим не измерялось.
Для доступа с ноутбука держите открытым SSH-туннель:

```sh
ssh -N -L 127.0.0.1:8088:127.0.0.1:8080 hizeshi
```

Откройте `http://127.0.0.1:8088/` для доступа через SSH-туннель.

18 октября 2026 года владелец разрешил публичный показ организаторам без пароля.
Для существующего HTTP-порта 8080 включён публичный доступ Brev:
**https://8080-7sjr06h5.gobrev.dev/**. Вход NVIDIA не требуется.
Настройки SSH и Jupyter не изменялись. Доступ действует, пока работают сервер,
frontend и API; локальный SSH-туннель посетителям не нужен.

Посмотреть настройки и выбрать идентификатор именно HTTP-порта 8080:

```sh
brev ports ls hizeshi --json
```

Публичный режим этого порта включается через `brev ports update PORT_ID --public`.
Для возврата к доступу по NVIDIA-аккаунту используйте
`brev ports update PORT_ID --authorize user@example.com`, указав нужный адрес.
Не применяйте настройки сайта к Jupyter или системному SSH-порту.
Публичный frontend обслуживается из собранного Docker-образа; каталоги обучающих
данных и локальных страниц разметки в его web-root не входят. Не добавляйте их
в frontend-образ. Видеозагрузка и очередь анализа на этом адресе доступны посетителям.

## Два GPU-кандидата

`train_gpu_vlm.py` поддерживает Qwen2.5-VL-3B/7B-Instruct и Qwen3-VL-2B/4B-Instruct.
Официальные Safetensors загружаются на закреплённой ревизии, без стороннего
Python-кода. Проверка прямого и обратного прохода на искусственных кадрах прошла
для обеих: около 4.48 и 3.39 ГБ пиковых выделений GPU соответственно.
Это проверка исполнимости, а не завершённое обучение на банковских данных.

Подготовщик `prepare_gpu_dataset.py` создаёт приватный набор: 40 уникальных
видео, 276 окон, по четыре кадра 336×336. У положительных обучающих роликов
используются только окрестности размеченных точек; валидация сканируется равномерно,
не используя точки для выбора входов. Разделение остаётся 32/8, точные копии
сгруппированы; связанные сессии ещё требуют проверки человеком.
Перенос кадров на внешний сервер требует явного разрешения владельца данных.

```sh
~/rat-ai-gpu-env/bin/python ai/tools/train_gpu_vlm.py --model qwen25 --dataset ~/rat-ai-runs/dataset --output ~/rat-ai-runs/qwen25 --epochs 2
~/rat-ai-gpu-env/bin/python ai/tools/train_gpu_vlm.py --model qwen3 --dataset ~/rat-ai-runs/dataset --output ~/rat-ai-runs/qwen3 --epochs 2
~/rat-ai-gpu-env/bin/python ai/tools/compare_gpu_models.py --first ~/rat-ai-runs/qwen25/report.json --second ~/rat-ai-runs/qwen3/report.json --output ~/rat-ai-runs/comparison.json
```

Обучаются LoRA-адаптеры языковых attention-проекций, визуальный энкодер заморожен.
Маска ошибки включает только ответ ассистента. Прогоны выполняются по очереди;
публикуются агрегаты. Приватные кадры, адаптеры и отчёты по отдельным видео остаются
в окружении команды. `compare_gpu_models.py` проверяет одинаковые видео, метки,
таймкоды и точки и сравнивает обе модели с фиксированным средним их баллов.
Совместный ответ не считается улучшением автоматически. Перебор на восьми
роликах не заменяет независимую проверку и разметку типов действий.
