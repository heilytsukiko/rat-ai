# Работа с ИИ-модулем

После клонирования репозитория коллеги могут запускать текущий детектор без
датасета и повторного обучения. В пакет включены экспериментальные веса около
4 МБ в формате Safetensors. Их качество пока недостаточно: на восьми
валидационных роликах после временного подтверждения получены 4 верных
срабатывания, 3 ложные тревоги и 1 верное отклонение. Это повторно использованная
выборка, а не независимая проверка качества.

## Установка

Python 3.12 x64. Проверено на Windows CPU; команда для Linux приведена ниже,
но отдельная проверка Linux пока не выполнена. Для компактной модели не нужны
NVIDIA, NPU или OpenVINO. Интернет нужен для первоначальной установки пакетов.

Windows, из корня клонированного репозитория:

```powershell
py -3.12 -m venv ai/.venv
ai/.venv/Scripts/python.exe -m pip install -e ./ai --extra-index-url https://download.pytorch.org/whl/cpu
ai/.venv/Scripts/python.exe ai/tools/infer_detector.py --video "C:\path\video.mov" --output ai/local/prediction.json
```

Linux, из корня репозитория:

```sh
python3.12 -m venv ai/.venv
ai/.venv/bin/python -m pip install -e ./ai --extra-index-url https://download.pytorch.org/whl/cpu
ai/.venv/bin/python ai/tools/infer_detector.py --video /path/video.mov --output ai/local/prediction.json
```

Во время обработки видео пакет не скачивает веса и не делает сетевых запросов.
При замене файлов весов проверяется SHA-256 из соседнего манифеста. Для обучения
и подготовки таблицы добавьте extra `training`: `-e "./ai[training]"`. Загрузчики
Qwen требуют отдельный extra `qwen` и не нужны для первого запуска детектора.

## Вызов из Python

```python
from rat_ai import VideoDetector

detector = VideoDetector(threads=4)  # загрузить один раз в локальном worker
result = detector.analyze_video("/absolute/path/video.mov")
```

При установке пакета его можно импортировать из папки backend и любого другого
рабочего каталога. Веб-серверу следует выполнять анализ в ограниченной очереди
фонового worker, чтобы обработка видео не блокировала цикл HTTP-запросов.
Число CPU-потоков задаётся для процесса; рассчитывайте его на весь worker.

Основные поля результата:

| Поле | Значение |
| --- | --- |
| `candidates` | Группы минимум из двух соседних окон со срабатыванием |
| `candidates[].timecode_sec` | Время существующего окна, ближайшего к среднему времени группы |
| `candidates[].score` | Некалиброванный балл модели, не гарантия достоверности |
| `video_score`, `peak_time_sec` | Максимальный балл по ролику и его время |
| `scan_times_sec`, `scan_scores` | Полная последовательность оценённых окон |
| `threshold` | Применённый порог, по умолчанию 0.5 |
| `candidate_policy` | Подтверждение: `min_windows=2`, `representative=center` |
| `processing_sec` | Декодирование и анализ после загрузки модели |
| `experimental` | Всегда `true` для текущей версии |

Ошибки чтения файла, повреждённого чекпойнта или обработки вызывают исключение.
Их нужно преобразовывать в статус задачи `failed`. Они не означают отсутствие
нарушения. Пустой список кандидатов также пока не является проверенным юридическим
заключением: модель выдаёт только статистические оценки.

`video_score` остаётся максимумом сырых окон: высокий балл может быть одиночным
и не дать ни одного подтверждённого кандидата. Интерфейс использует `candidates`.
Балл кандидата относится к выбранному окну и может отличаться от максимума группы.
Фильтр способен пропустить короткое действие; на проверке совпали 3 из 4 размеченных
точек в пределах 2 секунд. Настройка проверена при шаге сканирования 2 секунды.
Исходный локальный `.pt` не содержит новой политики; для актуального поведения
используйте пакетный Safetensors и соседний JSON, которые загружаются по умолчанию.

## Граница с существующим backend

Текущий backend запускает `ANALYZER_COMMAND` с аргументами `--video` и `--output`
и требует JSON со строго заданными `verdict`, `violations`, `type`, `description`,
`source` и `evidence_timestamps_sec`. Это описано в `backend/README.md`.

В стандартном режиме `ANALYSIS_MODE=strict` JSON `infer_detector.py`
не соответствует этой схеме. Для сквозной локальной проверки добавлен явный режим
`ANALYSIS_MODE=experimental`: он принимает сырые кандидаты, извлекает кадры и
отображает их на настоящем фронтенде без заключения о нарушении.
См. [запуск всего сервиса](LOCAL_STACK.md). Для полного контракта жюри нужны:

1. Установить наблюдаемый тип события и проверить последовательность действий.
2. Привязать его к реальному проверенному правилу и источнику.
3. Собрать событие по контракту backend с таймкодом и временем кадра.
4. Передать backend извлечение JPEG-кадров и управление задачей.

Из бинарного балла нельзя достоверно получить нормативный источник или тип
нарушения. Поэтому этот пакет не выдаёт фиктивных источников или готового вердикта
для жюри. Модель и её результаты не включены в Docker backend автоматически.

## Совместная разработка

Серверный запуск `infer_detector.py --describe-with-config <config.json>`
добавляет необязательное поле `observation_draft` в описанные кандидаты и
`observation_model=Qwen/Qwen2.5-VL-7B-Instruct` в корень ответа.
Описываются максимум восемь кандидатов; остальные остаются в результате.
Времена, баллы и политика детектора не меняются. Текст — черновик наблюдения,
не метка нарушения. Без параметра GPU-модель не загружается.

Экспериментальный backend проверяет объявленную модель и непустой текст до
1600 символов. Для описанных событий извлекаются до трёх различных JPEG:
время кандидата и контекст ±3.5 секунды с ограничением длительностью ролика.
Frontend помечает текст как требующий проверки человеком. Строгий контракт
для нормативных заключений этим расширением не заменяется.

- Модель и видеоподготовка: `ai/rat_ai/`.
- Подготовка датасета, обучение и диагностические команды: `ai/tools/`.
- Веса без аннотаций и путей: `ai/rat_ai/artifacts/`.
- Личные видео, разметка, кэш, исходные чекпойнты: только `ai/local/`, вне Git.
- Изменения модели проверяются командой `python -m unittest discover -s ai/tests -v`.

Перед добавлением новых весов используйте `export_detector.py`: полный `.pt`
чекпойнт обучения содержит приватный `sample_spec`, его публиковать не нужно.
Инструкции воспроизведения обучения и ограничения — в `ai/README.md`.
