# Backend RAT AI

FastAPI API по контракту Datathon 26. Работает локально: SQLite, ограниченная очередь в одном процессе, FFmpeg и внешний локальный AI-процесс. Видео удаляется после обработки; результаты и JPEG base64 остаются в SQLite. Идентификация лиц и облачные AI API не используются сервером.

**Статус:** сервер и контракт интеграции готовы. В `ai/` есть экспериментальный обученный детектор и [инструкция для команды](../ai/INTEGRATION.md); датасет не публикуется. Для него добавлен явный режим `ANALYSIS_MODE=experimental`: сервер возвращает кандидаты и кадры без юридического вердикта, UI показывает их как эксперимент. По умолчанию действует `strict` со схемой ниже: типы событий и нормативные источники ещё нужно добавить. Без настройки совместимого локального AI-процесса анализ завершится `failed`, а не фиктивным `no_violation`. Фронтенд подключён к API через серверный proxy (Vite в разработке, Nginx в корневом Docker Compose). Ключ подставляется proxy и не передаётся в браузерную сборку.

## Запуск

Готовый запуск UI, API и CPU-модели — из корня репозитория:

```sh
python3 tools/configure_local.py
docker compose up --build -d --wait
```

Интерфейс: http://127.0.0.1:8080. Образ включает FFmpeg, зависимости и опубликованные веса. В примере конфигурации выбран `experimental`; если переменная отсутствует, код API использует `strict`. Для запуска только backend из этой папки: `docker compose up --build -d`, API на http://127.0.0.1:8000.

Для разработки без Docker используйте [локальный launcher](../ai/LOCAL_STACK.md): он настраивает команду модели и общий ключ proxy автоматически. Пути `/opt/ai/` из `.env.example` относятся к контейнеру.

OpenAPI: `/docs`, `/openapi.json`. `/health` проверяет доступность сервера, а не готовность модели. Размещайте за HTTPS reverse proxy с ограничением тела запроса (например 110 MB) и таймаутами. Приложение ограничивает размер файла после multipart-разбора; лимит тела на proxy защищает также от больших multipart-запросов.

## API

```sh
curl -X POST http://localhost:8000/api/v1/analyze -H "X-API-Key: YOUR_KEY" -F "file=@video.mov"
# 202 {"job_id":"..."}
curl http://localhost:8000/api/v1/jobs/JOB_ID -H "X-API-Key: YOUR_KEY"
```

Опрос раз в 1–2 секунды. Статусы: `processing`, `done`, `failed`. В строгом режиме в `done`: `verdict` (`violation` / `no_violation`), `violations`, `duration_sec`. Каждое событие содержит `type`, `timecode_sec`, `description`, `source` и 1–3 `evidence_frames` с `timestamp_sec` и `image_base64` (JPEG без data URL префикса). В `failed`: `error`. Ошибки: 401 ключ, 404 задача, 413 размер, 415 расширение, 422 пустой файл/поле, 429 очередь заполнена. Принимаются MOV и MP4; фактический контейнер проверяет ffprobe.

## Контракт локальной модели

`ANALYZER_COMMAND` — JSON-массив аргументов, запускается без shell. Сервер добавляет `--video ABSOLUTE_PATH --output ABSOLUTE_JSON_PATH`. Процесс должен завершиться с кодом 0 и записать UTF-8 JSON:

```json
{
  "verdict": "violation",
  "violations": [{
    "type": "Тип наблюдаемого события",
    "timecode_sec": 12.0,
    "description": "Наблюдаемое действие и основание для проверки человеком",
    "source": {
      "title": "Название проверенного документа РК",
      "section": "Проверенный пункт или раздел",
      "url": "https://adilet.zan.kz/rus/docs/REPLACE_WITH_VERIFIED_DOCUMENT"
    },
    "evidence_timestamps_sec": [12.0]
  }]
}
```

Это пример схемы, а не нормативное утверждение. Реальные категории и источники должна предоставить команда модели после исследования актов РК; backend не выдумывает правила. Проверка домена ссылки не подтверждает юридическую корректность. Для отсутствия признаков: `{"verdict":"no_violation","violations":[]}`. Результат предназначен для проверки человеком.

Длительность видео до 180 секунд. Таймкоды внутри видео, кадры в пределах 5 секунд от события. Бюджет subprocess-этапов — до 240 секунд, но не позже пяти минут с начала приёма файла. Время загрузки и очереди вычитается из общего бюджета; просроченная задача завершается ошибкой, не запуская модель. Для проверки жюри отправляйте видео последовательно: при перегрузке соблюдение общего лимита 5 минут не гарантируется. Задачи, прерванные перезапуском, получают `failed`; оставшиеся служебные видео удаляются при старте. Не запускайте несколько Uvicorn workers/реплик с одной БД.

Хранение: `DATA_DIR` (по умолчанию `storage`). Для удаления данных остановите сервис и удалите storage / Docker volume. Автоматического срока хранения результатов пока нет; настройте удаление по условиям датасета. Логи могут содержать диагностику локальной модели; не публикуйте их.

## Экспериментальная модель через весь сервис

Для локального запуска backend + frontend + настоящего детектора используйте
[общую команду запуска](../ai/LOCAL_STACK.md). В этом режиме `done` содержит
`analysis_mode: "experimental"`, `experimental: true`, `candidates`, `threshold`,
`model`, `duration_sec` и сырые баллы. Кандидаты содержат `timecode_sec`, `score`,
границы выделенных окон и реальные JPEG `evidence_frames`.
Поля `verdict` и `violations` отсутствуют. Пустой список кандидатов не означает
`no_violation`. Это режим интеграционной проверки, а не контракт сдачи жюри.

Сервер проверяет баллы, таймкоды, соответствие пика сканированию и извлекает кадры
тем же FFmpeg и с тем же бюджетом времени, что в строгом режиме. Исходная схема
`Prediction` остаётся строгой и не принимает сырые результаты детектора.

## Тесты

```sh
python -m pip install pytest httpx
python -m pytest tests -q
```

Тесты API используют подменённую модель; они не измеряют качество распознавания. Для сдачи нужны реальная модель, проверенные нормативные ссылки, интеграция UI, оценка на датасете и публичный HTTPS адрес.
