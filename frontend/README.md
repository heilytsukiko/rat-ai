# Frontend

React + TypeScript + Vite. Интерфейс загружает видео в backend и показывает реальные статусы, вердикт, события, нормативные источники и JPEG-кадры. Демонстрационные данные используются только тестами, не страницей приложения.

## Локальный запуск

1. Запустите backend по инструкции в `../backend/README.md`, задав `API_KEY` и локальную модель.
2. Скопируйте `frontend/.env.example` в `frontend/.env`.
3. Задайте `BACKEND_API_KEY`, равный `API_KEY` backend, и при необходимости `BACKEND_URL` (по умолчанию `http://127.0.0.1:8000`).
4. Из папки frontend: `npm ci`, затем `npm run dev`.

Откройте адрес Vite, выберите MOV до 100 МБ и нажмите «Проверить видео». Vite пересылает `/api` на backend, добавляя ключ на сервере. После изменения `.env` перезапустите Vite. Не используйте префикс `VITE_` для ключа: он не должен попадать в сборку браузера.

Сервис отправляет multipart `file` на `POST /api/v1/analyze`, затем опрашивает `GET /api/v1/jobs/{job_id}` раз в 1,5 секунды до `done` или `failed`. Показывается фактический прогресс отправки файла. Общее ожидание ограничено пятью минутами. «Прекратить ожидание» отменяет загрузку или опрос в браузере; backend не имеет метода отмены и может продолжать уже принятую задачу. Повторная проверка создаёт новую задачу.

Ошибки ключа, формата, размера, очереди и обработки отображаются без фиктивного успешного результата. Если локальная модель не подключена, backend вернёт `failed`.

Для настоящего компактного детектора есть [общий локальный запуск](../ai/LOCAL_STACK.md).
При `ANALYSIS_MODE=experimental` backend возвращает кандидаты с реальными кадрами.
UI явно показывает экспериментальный анализ и отсутствие готового заключения.
Даже при пустом результате он не сообщает, что нарушений нет. В обычном режиме
сохраняется исходный контракт с вердиктом, типами событий и нормативными ссылками.

## Запуск всего сервиса в Docker

Из корня репозитория после создания `backend/.env`: `docker compose up --build`. UI: `http://localhost:8080`. Nginx раздаёт сборку и проксирует `/api`, подставляя `API_KEY` из окружения. Модель доступна backend в `/models`; настройте `ANALYZER_COMMAND` и зависимости модели по backend README.

Vite proxy работает только в dev. Для production используйте Docker/Nginx или аналогичный серверный proxy. `vite preview` сам по себе не подключает backend. Не размещайте сборку без `/api` proxy.

Публичный UI разрешает посетителям запускать анализ через proxy. Для внутреннего развёртывания ограничьте доступ к UI/proxy на reverse proxy. API жюри остаётся доступен непосредственно на backend с `X-API-Key`; корневой compose не публикует его порт, внешний маршрут настраивается при развёртывании.

## Проверки

```sh
npm test
npm run build
```

`services/apiAnalysisService.ts` — загрузка, опрос, преобразование snake_case и JPEG base64 в типы интерфейса. `hooks/useAnalysis.ts` — состояние, таймаут, отмена и повтор. Тесты API-сервиса подменяют сеть; качество AI ими не измеряется.

Ответы сервера проверяются до отображения: статусы, согласованность вердикта, события, конечные таймкоды в пределах записи, JPEG base64 и структура нормативных ссылок. Повреждённый JSON или ошибка сети показывают сообщение вместо сбоя интерфейса. Остановка опроса не меняет уже завершённую загрузку на «отменённую».
