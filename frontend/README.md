# Frontend

React + TypeScript + Vite. Внешние UI-библиотеки и облачные сервисы не нужны; иконки — lucide-react. Все стили, схемы кадров и мок-данные находятся в проекте. Шрифты системные, запросов к Google Fonts нет.

## Структура

```text
src/
  app/                         # корневой компонент и общие стили/токены
  assets/                      # локальные схемы кадров для демонстрации
  components/                  # шапка, подвал и общие UI-компоненты
    ui/                        # Modal, SectionLabel
  features/
    analysis/
      AnalysisPage.tsx         # композиция страницы
      components/              # загрузка, этапы, события, кадры, основания
      hooks/useAnalysis.ts     # состояние сценария и отмена запросов
      model/                   # типы, форматирование, валидация
      mocks/                   # данные демонстрационных результатов
      services/                # заменяемый сервис анализа
  test/                        # настройка тестового окружения
```

## Демонстрация

При открытии отображается готовый пример с двумя условными событиями. Выберите сценарий сверху и нажмите «Запустить пример»: доступны события, отсутствие нарушений и ошибка. Для проверки сценария выбора файла перетащите `.mov` или нажмите «выберите файл», затем «Запустить проверку».

Проверяются расширение (без учёта регистра), непустой файл и размер до 100 МБ. Лимит 100 МБ — временное ограничение интерфейса, а не требование API; настройка находится в `model/validation.ts`. MIME-тип не используется как единственный признак, поскольку ОС может не передать его для MOV.

Загрузка и обработка имитируются. После выбора своего видео результат всё равно содержит условные события и схемы, а не результаты реального анализа. Фиктивная длительность не присваивается пользовательскому файлу. Нормативные источники оставлены незаполненными: выдуманных документов и пунктов нет.

Во время проверки можно отменить задачу. Смена файла сбрасывает старый результат; отменённая задача не может восстановить его поздним ответом. Ошибка не отображается вместе со старым успешным вердиктом. Выбор события меняет описание и схему кадра; кадр открывается в модальном окне (закрывается кнопкой, Escape и нажатием на фон).

## Подключение backend

Компоненты используют внутренние типы из `model/types.ts` и интерфейс `AnalysisService`. `useAnalysis` принимает реализацию сервиса; по умолчанию используется `mockAnalysisService`. Для интеграции нужно добавить HTTP-адаптер с тем же интерфейсом и заменить реализацию по умолчанию.

Ожидаемый API из кейса:

- `POST /api/v1/analyze`: `multipart/form-data`, поле `file`, заголовок `X-API-Key`; ответ содержит `job_id`.
- `GET /api/v1/jobs/{job_id}`: `processing`, `done` или `failed`.
- Завершённый ответ: `verdict` (`violation` / `no_violation`) и `violations` с `type`, `timecode_sec`, `description`, `evidence_frames` (`timestamp_sec`, `image_base64`).

Адаптер должен преобразовать snake_case API в типы приложения, сформировать стабильные ID событий, преобразовать JPEG base64 в URL, обрабатывать ошибки HTTP/сети и ограничить polling по времени. Передавайте AbortSignal в загрузку, polling и задержки; для реального прогресса загрузки используйте транспорт с upload-progress. Процент обработки нельзя выдумывать — показывайте неопределённый прогресс, если backend не присылает его.

Нормативные источники в исходной схеме API отсутствуют. С backend необходимо согласовать дополнительный объект источника (название, пункт, URL) для каждого события. Интерфейс уже поддерживает необязательный `source`; до интеграции показывает «Источник пока не привязан».

API-ключи не следует коммитить или помещать в `VITE_*`: такие переменные попадают в клиентскую сборку. Согласуйте передачу ключа через сессию либо серверный прокси. Сейчас приложение не содержит API-ключей и не делает сетевых запросов к backend.

## Проверки

```bash
npm ci
npm test
npm run build
```

Тесты расположены рядом с проверяемыми модулями. Проверяются валидация файлов, порядок стадий, чистый и ошибочный результаты, отмена и защита состояния от запоздалых ответов.

Исходные пять HTML-макетов и их ZIP остаются локально в `designs/` и не входят в React-приложение или git.
